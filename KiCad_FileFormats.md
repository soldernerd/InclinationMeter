# KiCad 10 File Format Reference — Practical Implementation Notes

**Purpose:** Hands-on reference for programmatic reading/writing of KiCad 10 files. Complements `KiCad_SchematicsGuide.md` (design best practices) with format details and pitfalls learned during implementation.  
**Target:** KiCad 10, file format version `20250114`.

---

## 1. File Overview

A KiCad project consists of these files:

| File | Format | Purpose |
|------|--------|---------|
| `*.kicad_pro` | JSON | Project settings (net classes, board defaults, library pins) |
| `*.kicad_sch` | S-expression | Schematic sheet (one per sheet in hierarchy) |
| `sym-lib-table` | S-expression | Symbol library lookup table (project-local) |
| `fp-lib-table` | S-expression | Footprint library lookup table (project-local) |
| `*.kicad_sym` | S-expression | Symbol library (one or more symbols per file) |
| `*.kicad_pcb` | S-expression | PCB layout (not covered here) |

---

## 2. S-Expression Format Basics

KiCad uses a Lisp-like S-expression syntax. Key rules:

- Parenthesized lists: `(keyword arg1 arg2 ...)`
- Strings with special chars are quoted: `(property "Value" "100nF")`
- Numbers are unquoted: `(at 25.4 50.8 0)`
- UUIDs are quoted strings: `(uuid "a1b2c3d4-...")`
- Indentation uses tabs in KiCad-generated files (spaces also accepted)
- No trailing commas, no separators between elements

### Parsing Gotcha
When extracting a symbol from a `.kicad_sym` file by text search, use plain string matching (`str.find()`), **not** `re.escape()` followed by `str.find()`. The `re.escape()` function adds backslashes (e.g., `DMG2305UX\-13`) that break literal string searching. Either use raw `str.find()` or use actual regex with `re.search()`.

## 3. Symbol Library Files (.kicad_sym)

### Structure
```
(kicad_symbol_lib
  (version 20211014)
  (generator "...")

  (symbol "SYMBOL_NAME"
    (in_bom yes)
    (on_board yes)
    (property "Reference" "U" (at 0 7.62 0) (effects ...))
    (property "Value" "SYMBOL_NAME" (at 0 -7.62 0) (effects ...))
    (property "Footprint" "Package:Footprint" (at ...) (effects ... hide))
    (property "Datasheet" "url" (at ...) (effects ... hide))
    ...additional properties...

    (symbol "SYMBOL_NAME_0_1"      ; Graphics sub-symbol (unit 0 = common to all units)
      (rectangle (start ...) (end ...) (stroke ...) (fill ...))
      (pin TYPE STYLE
        (at X Y ROT)
        (length L)
        (name "PIN_NAME" (effects ...))
        (number "PIN_NUM" (effects ...))
      )
      ...more pins...
    )
    (symbol "SYMBOL_NAME_1_1"      ; Unit 1 additional graphics (if multi-unit)
      ...
    )
  )
)
```

### Sub-Symbol Naming Convention
- `SYMBOL_NAME_0_1` — graphics common to all units (unit 0), "de Morgan" variant 1
- `SYMBOL_NAME_1_1` — unit 1 specific graphics, variant 1
- `SYMBOL_NAME_2_1` — unit 2 specific graphics, variant 1
- For single-unit symbols, pins are typically in `_0_1` (or sometimes `_1_1`)
- Both `_0_1` and `_1_1` are children of the parent `SYMBOL_NAME` symbol

### Pin Definition
```
(pin TYPE STYLE
  (at X Y ROTATION)    ; Connection point in symbol coords (Y-up)
  (length LENGTH)      ; How far the pin line extends from connection point
  (name "NAME" ...)
  (number "NUM" ...)
)
```

**Pin types:** `input`, `output`, `bidirectional`, `passive`, `power_in`, `power_out`, `unspecified`, `free`, `open_collector`, `open_emitter`, `no_connect`, `tri_state`

**Pin styles:** `line`, `inverted`, `clock`, `inverted_clock`, `input_low`, `clock_low`, `output_low`, `edge_clock_high`, `non_logic`

**Pin rotation** (in symbol coords, Y-up):
| Rotation | Pin line extends | Connection point is on |
|----------|-----------------|----------------------|
| 0° | RIGHT from body | LEFT side (wire connects on left) |
| 90° | UP from body | BOTTOM side |
| 180° | LEFT from body | RIGHT side (wire connects on right) |
| 270° | DOWN from body | TOP side |

The `(at X Y)` gives the **wire connection endpoint** — this is where you must place wires in the schematic.

### Extracting Pin Positions
To get the wire connection point for each pin, parse the `(pin ... (at X Y ROT) ...)` inside the sub-symbols. The `(at X Y)` value is directly the connection point in symbol-local coordinates.

Example from DW01A:
```
(pin unspecified line
  (at -12.70 2.54 0)    ; Pin 1 "OD" — connection at (-12.70, 2.54)
  (length 5.08)
  (name "OD" ...)
  (number "1" ...)
)
```

## 4. JLCPCB / EasyEDA Converted Libraries

Libraries generated by `easyeda2kicad.py` (from JLCPCB/LCSC) have these characteristics:

### Symbol Name Convention
- **Slashes `/` are replaced with underscores `_`** in symbol names
  - Manufacturer part: `LP5907MFX-3.3/NOPB` → Symbol name: `LP5907MFX-3.3_NOPB`
  - `RN4871-I/RM128` → `RN4871-I_RM128`
  - `24LC256-I/ST` → `24LC256-I_ST`
- Hyphens `-` are preserved: `DMG2305UX-13` stays `DMG2305UX-13`
- LCSC part numbers may be appended: `TP4056_C382139`

### Properties
These libraries include extra properties not in standard KiCad libraries:
- `"LCSC Part"` — JLCPCB/LCSC part number (e.g., `"C85680"`)
- `"MPN"` — Manufacturer Part Number
- `"Manufacturer"` — Manufacturer name (often `"null"` for generics)
- Properties use `(id N)` identifiers (legacy format from older KiCad versions)

### Pin Layout
- Pins use **physical package order**, not functional grouping
- All pins typically typed as `unspecified` (not `input`/`output`/`power_in`)
- Pin arrangement reflects the IC's physical pinout, not schematic conventions

### Footprint References
- Footprints reference the library's own namespace: `"DW01A:SOT-23-6_L2.9-W1.6-P0.95-LS2.8-BL"`
- These won't resolve unless the matching `.kicad_mod` footprint library is also installed
- For JLCPCB assembly, the footprint name matters less than the LCSC part number

### Library Version
- Use `(version 20211014)` — older than KiCad 10's native format
- KiCad 10 reads these without issue; it silently upgrades on re-save

## 5. Schematic Files (.kicad_sch)

### Top-Level Structure
```
(kicad_sch
  (version 20250114)
  (generator "eeschema")
  (generator_version "10.0")
  (uuid "ROOT_UUID")
  (paper "A3")                    ; or "A4"
  (title_block
    (title "Sheet Title")
    (date "2026-04-14")
    (rev "0.1")
  )
  (lib_symbols
    ; ALL symbol definitions used on this sheet, embedded in full
  )
  ; Content elements in order:
  (junction ...)                   ; Wire junction dots
  (wire ...)                       ; Wire segments
  (text ...)                       ; Freestanding text annotations
  (label ...)                      ; Local net labels
  (global_label ...)               ; Global net labels
  (symbol ...)                     ; Component instances
  (sheet ...)                      ; Sub-sheet references (root sheet only)
  (sheet_instances ...)            ; Page number assignments
  (embedded_fonts no)
)
```

### Critical Rule: lib_symbols Must Embed Everything
Every symbol used on a sheet must have its **complete definition** embedded in `(lib_symbols ...)`. This includes:
- Component symbols (ICs, passives)
- Power symbols (GND, +3V3, etc.)
- The definitions are copies — modifying them here doesn't change the source library

When embedding a local library symbol, rename it to avoid conflicts:
```python
# Rename "DW01A" to "local_DW01A:DW01A" in the embedded definition
sym_text = sym_text.replace(
    '(symbol "DW01A"',
    '(symbol "local_DW01A:DW01A"'
)
```
This must also rename all sub-symbols: `DW01A_0_1` → `local_DW01A:DW01A_0_1`.

### Symbol Instance (Component Placement)
```
(symbol
  (lib_id "local_TP4056:TP4056_C382139")   ; References embedded lib_symbol
  (at 175 72 0)                              ; X Y ROTATION in mm
  (unit 1)                                   ; Which unit (for multi-unit symbols)
  (exclude_from_sim no)
  (in_bom yes)
  (on_board yes)
  (dnp no)                                   ; Do Not Populate
  (uuid "UNIQUE_UUID")
  (property "Reference" "U3"
    (at 177.54 69.46 0)
    (effects (font (size 1.27 1.27)) (justify left))
  )
  (property "Value" "TP4056"
    (at 177.54 66.92 0)
    (effects (font (size 1.27 1.27)) (justify left))
  )
  (property "Footprint" "Package_SO:SOP-8_3.9x4.9mm_P1.27mm"
    (at 175 72 0)
    (effects (font (size 1.27 1.27)) (hide yes))
  )
  (property "Datasheet" "~"
    (at 175 72 0)
    (effects (font (size 1.27 1.27)) (hide yes))
  )
  (property "Description" ""
    (at 175 72 0)
    (effects (font (size 1.27 1.27)) (hide yes))
  )
  (instances
    (project "ProjectName"
      (path "/ROOT_UUID"                     ; or "/ROOT_UUID/SHEET_UUID"
        (reference "U3")
        (unit 1)
      )
    )
  )
)
```

### Power Symbol Instances
Power symbols (GND, +3V3, etc.) are special:
- They are **both** a `lib_symbols` definition **and** a `symbol` instance
- Their `lib_id` uses the `power:` prefix: `"power:GND"`, `"power:+3V3"`
- The `(power)` flag in the lib_symbol definition makes the net implicitly global
- Reference designators use `#PWR` prefix and should be hidden
- Each placed power symbol gets a unique `#PWR0xx` reference

### Wire Segments
```
(wire
  (pts (xy X1 Y1) (xy X2 Y2))
  (stroke (width 0) (type default))
  (uuid "UNIQUE_UUID")
)
```
- Wires are always point-to-point segments (two endpoints)
- Only orthogonal wires (horizontal or vertical) — no diagonals
- Wire endpoints must exactly match pin connection points for electrical connection
- A 0.01mm offset will cause an unconnected pin error

### Junction Dots
```
(junction
  (at X Y)
  (diameter 0)
  (color 0 0 0 0)
  (uuid "UNIQUE_UUID")
)
```
Required wherever 3+ wires meet at a point. Without a junction, KiCad treats crossing wires as unconnected.

### Labels
```
; Local net label (single sheet scope)
(label "NET_NAME"
  (at X Y ROTATION)
  (effects (font (size 1.27 1.27)) (justify left bottom))
  (uuid "UNIQUE_UUID")
)

; Global label (all sheets)
(global_label "NET_NAME"
  (shape input)                    ; input, output, bidirectional, tri_state, passive
  (at X Y ROTATION)
  (effects (font (size 1.27 1.27)) (justify left))
  (uuid "UNIQUE_UUID")
  (property "Intersheets" ""
    (at X Y 0)
    (effects (font (size 1.27 1.27)) (hide yes))
  )
)
```

**Label rotation:**
| Rotation | Text reads | Wire connects from |
|----------|-----------|-------------------|
| 0° | Left to right | Left side |
| 180° | Left to right | Right side |
| 90° | Bottom to top | Bottom side |
| 270° | Top to bottom | Top side |

For a label at 0°, the connection point is on the **left** — attach wire to the label's `(at X Y)` position from the left.  
For a label at 180°, the connection point is on the **right** — attach wire to the label's position from the right.

### Freestanding Text
```
(text "Annotation text"
  (at X Y ROTATION)
  (effects (font (size 2.54 2.54)) (justify left bottom))
  (uuid "UNIQUE_UUID")
)
```

### Dashed Rectangle (Section Border)
Drawn as a `(polyline ...)` inside a `(symbol ...)` wrapper — but for schematic annotations, use raw polyline with dashed stroke. In practice, four `(wire ...)` segments with dashed type don't exist — instead use a `(polyline ...)` at the schematic level (KiCad 10):
```
(polyline
  (pts (xy X1 Y1) (xy X2 Y1) (xy X2 Y2) (xy X1 Y2) (xy X1 Y1))
  (stroke (width 0.254) (type dash))
  (uuid "UNIQUE_UUID")
)
```
Note: Older KiCad versions used `(rectangle ...)` at the schematic level; KiCad 10 uses `(polyline ...)` for free-form drawing.

## 6. Coordinate Systems

### The Two Coordinate Systems (Critical)

| Context | Y-axis | Used in |
|---------|--------|---------|
| Symbol definition (`.kicad_sym`) | **Y-up** (math convention) | Pin positions, body rectangle, graphics |
| Schematic file (`.kicad_sch`) | **Y-down** (screen convention) | Symbol placement, wires, labels |

### Pin Position Transform

Given:
- Symbol placed at schematic position `(sx, sy)` with rotation `R`
- Pin defined at symbol-local position `(px, py)` (Y-up coordinates)

The **wire connection point** in schematic coordinates (Y-down) is:

```
R =   0°:  wire_x = sx + px,  wire_y = sy - py
R =  90°:  wire_x = sx - py,  wire_y = sy - px
R = 180°:  wire_x = sx - px,  wire_y = sy + py
R = 270°:  wire_x = sx + py,  wire_y = sy + px
```

The Y-flip (`sy - py` at 0°) accounts for the coordinate system difference. At 90°, the rotation matrix and Y-flip combine.

### Worked Example
LP5907 symbol: pin 1 (IN) at local `(-7.62, 2.54)`, symbol placed at schematic `(260, 55)`, rotation 0°:
```
wire_x = 260 + (-7.62) = 252.38
wire_y = 55 - 2.54 = 52.46
```
Wire must connect to `(252.38, 52.46)` in the schematic.

## 7. Hierarchical Sheets

### Root Sheet
The root `.kicad_sch` contains `(sheet ...)` elements referencing sub-sheets:
```
(sheet
  (at 30 60)                      ; Position of the sheet box on root page
  (size 65 30)                    ; Width and height of the sheet box
  (exclude_from_sim no)
  (in_bom yes)
  (on_board yes)
  (dnp no)
  (stroke (width 0) (type solid))
  (fill (color 0 0 0 0.0000))
  (uuid "SHEET_UUID")             ; This UUID is used in instance paths
  (property "Sheetname" "Power Supply"
    (at 30 59.238 0)
    (effects (font (size 1.524 1.524)) (justify left bottom))
  )
  (property "Sheetfile" "power.kicad_sch"
    (at 30 90.762 0)
    (effects (font (size 1.524 1.524)) (justify left top))
  )
  (instances
    (project "ProjectName"
      (path "/ROOT_UUID"
        (page "2")
      )
    )
  )
)
```

### sheet_instances Block
The root sheet must also contain a `(sheet_instances ...)` block listing all sheet paths and their page numbers:
```
(sheet_instances
  (path "/"
    (page "1")
  )
  (path "/ROOT_UUID/SHEET1_UUID"
    (page "2")
  )
  (path "/ROOT_UUID/SHEET2_UUID"
    (page "3")
  )
)
```

### Instance Paths
Symbol instances on sub-sheets use the path format `"/ROOT_UUID/SHEET_UUID"`:
```
(instances
  (project "ProjectName"
    (path "/ROOT_UUID/SHEET_UUID"
      (reference "U3")
      (unit 1)
    )
  )
)
```

The `SHEET_UUID` must match the `(uuid ...)` in the root sheet's `(sheet ...)` element. If these don't match, KiCad won't assign correct reference designators.

### Inter-Sheet Connectivity
- **Global labels** connect nets across all sheets — same name = same net
- **Power symbols** are implicitly global — `GND` on any sheet connects to `GND` everywhere
- **Hierarchical pins** on sheet boxes are NOT needed when using global labels (they're for explicit hierarchical designs)

## 9. Library Tables

### sym-lib-table
```
(sym_lib_table
  (version 7)
  (lib (name "local_DW01A")(type "KiCad")(uri "${KIPRJMOD}/../Libraries/KiCad/DW01A.kicad_sym")(options "")(descr ""))
  ...
)
```
- `${KIPRJMOD}` expands to the directory containing `.kicad_pro`
- Use relative paths via `${KIPRJMOD}` for portability
- `type` is always `"KiCad"` for `.kicad_sym` files

### fp-lib-table
```
(fp_lib_table
  (version 7)
  (lib (name "local_DW01A")(type "KiCad")(uri "${KIPRJMOD}/../Libraries/KiCad/DW01A.pretty")(options "")(descr ""))
  ...
)
```
- `.pretty` is a directory containing `.kicad_mod` files
- JLCPCB-converted libraries create one `.pretty` directory per component

## 10. Inline Symbol Definitions (No External Library Needed)

For common passives and power symbols, define them inline to avoid dependency on KiCad's built-in library paths (which vary by OS and installation).

### Resistor (Minimal)
```
(symbol "Device:R"
  (pin_names (offset 0))
  (exclude_from_sim no)
  (in_bom yes)
  (on_board yes)
  (property "Reference" "R" (at 2.032 0 90) (effects (font (size 1.27 1.27))))
  (property "Value" "R" (at -2.032 0 90) (effects (font (size 1.27 1.27))))
  (property "Footprint" "" (at 0 0 0) (effects (font (size 1.27 1.27)) (hide yes)))
  (property "Datasheet" "~" (at 0 0 0) (effects (font (size 1.27 1.27)) (hide yes)))
  (property "Description" "Resistor" (at 0 0 0) (effects (font (size 1.27 1.27)) (hide yes)))
  (symbol "R_0_1"
    (rectangle (start -1.016 3.81) (end 1.016 -3.81)
      (stroke (width 0) (type default)) (fill (type none)))
  )
  (symbol "R_1_1"
    (pin passive line (at 0 5.08 270) (length 1.27) (name "1" ...) (number "1" ...))
    (pin passive line (at 0 -5.08 90) (length 1.27) (name "2" ...) (number "2" ...))
  )
)
```
Pin 1 at `(0, 5.08)` → top, pin 2 at `(0, -5.08)` → bottom in symbol coords.

### Capacitor (Minimal)
Same structure as resistor with different body graphic (two parallel lines instead of rectangle).

### GND Power Symbol
```
(symbol "power:GND"
  (power)                          ; ← This flag makes it a power symbol
  (pin_names (offset 0))
  ...
  (symbol "GND_0_1"
    (polyline (pts (xy 0 0) (xy 0 -1.27) (xy 1.27 -1.27) (xy 0 -2.54) (xy -1.27 -1.27) (xy 0 -1.27))
      (stroke (width 0) (type default)) (fill (type none)))
  )
  (symbol "GND_1_1"
    (pin power_in line (at 0 0 270) (length 0)
      (name "GND" ...) (number "1" ...))
  )
)
```
- The `(power)` flag is essential — without it, the symbol won't create an implicit global net
- Pin type must be `power_in`
- Pin length is 0 — the connection point is at the symbol origin

## 11. UUID Requirements

Every element needs a unique UUID v4. KiCad will regenerate conflicting UUIDs on load, but this triggers warnings. Generate fresh UUIDs for:
- The schematic file itself (`(uuid "...")` at top level)
- Every `(symbol ...)` instance
- Every `(wire ...)` segment
- Every `(junction ...)`, `(label ...)`, `(global_label ...)`
- Every `(text ...)` and `(polyline ...)`
- Every `(sheet ...)` reference
- The instance path entries

In Python: `str(uuid.uuid4())` generates valid UUIDs.

## 12. Common Pitfalls

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| Pin endpoint off 1.27mm grid | Unconnected pin ERC errors | Ensure all pin `(at)` values are multiples of 1.27 |
| Wire doesn't exactly reach pin | "Wire not connected" | Use `pin()` transform function, don't estimate coords |
| `re.escape()` with `str.find()` | Symbols not found in library | Don't escape for literal string search |
| `/` in JLCPCB symbol names | Symbol extraction fails | Use `_` instead of `/` when referencing |
| Missing `lib_symbols` entry | Symbol appears as `?` box | Embed every used symbol in `(lib_symbols ...)` |
| Missing `(power)` flag | Power net not globally connected | Include `(power)` in power symbol definitions |
| Wrong instance path | Reference designators reset to `U?` | Path must be `/ROOT_UUID/SHEET_UUID` |
| `sheet_instances` missing entries | Page numbers show as `?` | List all sheets including root `/` |
| Duplicate UUIDs | Warning on load, possible corruption | Generate fresh UUID for every element |
| Sub-symbols not renamed | Symbol partially loads | When renaming `FOO` → `LIB:FOO`, also rename `FOO_0_1` → `LIB:FOO_0_1` |

## 13. Automating Pin Extraction

To avoid manually transcribing pin positions, parse `.kicad_sym` files:

```python
import re

def extract_pins(lib_path, symbol_name):
    """Extract pin {number: (x, y)} from a .kicad_sym file."""
    content = lib_path.read_text(encoding="utf-8")
    pins = {}
    # Find all pins in the symbol (including sub-symbols)
    pin_pattern = re.compile(
        r'\(pin\s+\w+\s+\w+\s*\n?\s*'
        r'\(at\s+([-\d.]+)\s+([-\d.]+)\s+\d+\)\s*\n?\s*'
        r'\(length\s+[-\d.]+\)\s*\n?\s*'
        r'\(name\s+"[^"]*"[^)]*\)\s*\n?\s*'
        r'\(number\s+"(\d+)"',
        re.MULTILINE
    )
    for m in pin_pattern.finditer(content):
        x, y, num = float(m.group(1)), float(m.group(2)), m.group(3)
        pins[num] = (x, y)
    return pins
```

This returns the pin connection points in symbol-local coordinates (Y-up). Apply the transform from Section 6 to get schematic coordinates.
